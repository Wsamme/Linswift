# 经典书籍处理与清洗说明

本文档说明 Linswift 如何把 `public/classic-books/` 下的原始英文 TXT 书籍清洗为可上架、可分章节、可做陌生词识别的公共经典书资源。

## 1. 原始文件放置规则

- 原始文本统一放在：
  - `public/classic-books/`
- 文件来源优先使用：
  - [Project Gutenberg](https://www.gutenberg.org/)
- 文件格式要求：
  - `.txt`
  - UTF-8 或可被 UTF-8 正常读取
- 文件命名建议：
  - 使用英文标题，单词之间用下划线连接
  - 例如：`Anne_of_Green_Gables.txt`

## 2. 上架一本新书需要改哪些地方

需要同时修改两处配置：

1. `scripts/prepare-classic-books.mjs`
   - 在 `BOOK_CONFIGS` 中注册新书
   - 指定：
     - `slug`
     - `fileName`
     - `title`
     - `author`
     - `bodyStartPattern`
     - `parser`

2. `src/data/classicBooks.ts`
   - 把这本书加入 `CLASSIC_BOOKS`
   - 配置：
     - 书名
     - 作者
     - `processedPath`
     - 封面主题 `coverTheme`
     - 排序 `sortOrder`

如果只加原始 TXT、不加这两处配置，前端不会展示，预处理也不会生成章节 JSON。

## 3. 清洗流程说明

经典书预处理脚本：

```bash
npm run prepare:classic-books
```

脚本位置：

- `scripts/prepare-classic-books.mjs`

主要处理步骤如下。

### 3.1 标准化文本

- 移除 UTF-8 BOM
- 把 `\r\n` 统一为 `\n`
- 把制表符替换成普通空格

### 3.2 去掉 Gutenberg 版权头尾

- 移除 `*** START OF THE PROJECT GUTENBERG EBOOK ... ***` 之前的说明
- 移除 `*** END OF THE PROJECT GUTENBERG EBOOK ... ***` 之后的内容

这一层的目的，是只保留正文可阅读内容，不把版权声明和分发说明带进阅读器。

### 3.3 清理非正文内容

当前脚本会尽量移除这些内容：

- `Contents / CONTENTS`
- 插画引用块
- `frontispiece`
- `Illustration:` 类说明
- 多余方括号包裹的插图标注

处理原则：

- 不保留正文以外的视觉引用代码
- 不把目录页内容误识别成章节正文
- 优先保住正文段落完整性

### 3.4 按段落切分

脚本会先把文本切成段落，再把章节标题提取为特殊标记，最后再生成结构化章节数据。

这一步的目标是：

- 让阅读器按自然段显示
- 为后续按页、按章节做陌生词识别提供更稳定的文本边界

### 3.5 按章节解析

目前支持几种常见解析器：

- `chapter`
  - 适用于 `CHAPTER I` 与章节标题分离的书
- `chapter-inline`
  - 适用于 `CHAPTER I. Chapter Title` 写在同一行的书
- `sherlock`
  - 适用于福尔摩斯短篇集的罗马数字故事标题
- `frankenstein`
  - 适用于 `Letter` + `Chapter` 混合结构
- `tale-of-two-cities`
  - 适用于 `Book the First` + `CHAPTER I` 的双层结构

新增书籍时，先看正文真实标题格式，再选 parser，不要仅凭目录页猜。

## 4. bodyStartPattern 的选法

`bodyStartPattern` 用来告诉脚本“正文从哪里开始”。

建议规则：

- 选择正文里第一次正式章节标题
- 避免匹配目录页中的同名标题
- 如果目录和正文都出现同一标题，脚本会取最后一次匹配，尽量落到正文起点

例如：

- `Anne of Green Gables`
  - 正文第一章是：
  - `CHAPTER I. Mrs. Rachel Lynde Is Surprised`
  - 适合用：

```js
/^CHAPTER I\. Mrs\. Rachel Lynde Is Surprised$/m
```

## 5. 生成结果

预处理输出目录：

- `public/classic-books/processed/`

每本书会生成一个 JSON，例如：

- `public/classic-books/processed/anne-of-green-gables.json`

同时会更新总清单：

- `public/classic-books/processed/manifest.json`

输出 JSON 主要包含：

- `slug`
- `title`
- `author`
- `chapterCount`
- `cleanedText`
- `chapters[]`

每个 `chapter` 包含：

- `id`
- `title`
- `sectionTitle`
- `paragraphs`
- `text`
- `wordCount`

## 6. 加书后的验证清单

新增或调整一本书后，至少做下面检查：

1. 运行：
   - `npm run prepare:classic-books`
2. 确认生成了对应的 `processed/*.json`
3. 打开 `manifest.json`，确认新书已入清单
4. 在书架公共书库中确认：
   - 能看到新书
   - 封面正常
   - 可加入书架
5. 打开阅读器检查：
   - 章节目录是否完整
   - 首章是否不是目录页
   - 插画说明、版权头尾是否未进入正文

## 7. 当前经验

- Gutenberg 文本的难点不在“下载”，而在“目录页和正文标题重复”。
- 最容易污染阅读体验的是：
  - 版权头尾
  - 目录页
  - 插画说明
- 封面、元数据、章节 JSON 必须一起维护，否则会上架成功但体验不完整。
